# 06 · 배포와 한계

온기길을 온라인에 올리는 법, 필요한 것(아주 적습니다), 그리고 — 솔직히 — 웹앱이 아직 **할 수 없는 것**.
설계서 §5, §6, §9 기준.

---

## 구조 요약

```
  PWA (설치형; 받는 사람 / 알리는 사람 / 도우미)  ──HTTPS──►  API (작고 상태 없음)
    Geolocation + DeviceOrientation (나침반)                  지점: 알림 · 주변 · 만료
    speechSynthesis (한국어 음성)                             피드백: 가져감 / 없음 / 부적절
    Wake Lock (안내 중 화면 켬)                               Directions: 호밍(기본) | 제공자 스텁
    선택한 지점 안내는 오프라인 동작                           저장: SQLite · 위치 뭉개기
```

- **프론트엔드:** PWA — 빌드 없음, 순수 JS 모듈, **외부 CDN 없음**, 한국어 우선, 큰 UI.
- **백엔드:** 작은 파이썬 **FastAPI** + **SQLite**. 알림/주변/피드백/만료, 위치 뭉개기, `Directions`
  인터페이스. **열쇠 없이 동작.**
- **데모 모드:** 완전히 클라이언트 측(미리 넣은 지점 + 걷는 흉내) — 백엔드 없이 링크로 음성을 들을 수
  있음.

---

## 열쇠 없이 배포

**1. 앱 (정적).** 앱이 빌드 없는 순수 파일이므로 정적 콘텐츠로 호스팅합니다:

- **GitHub Pages** — `app/` 폴더 제공; Pages를 켜면 데모가
  `https://clsoftlab-lang.github.io/ongigil/app/` 에 열립니다.
- 또는 다른 정적 호스트나 자체 nginx. 번들러·CDN·열쇠 없음.

**2. API.** FastAPI 서비스를 실행합니다(진입점은 `backend/README.md` 채워지는 대로), 예:

```bash
cd backend
pip install -e .
uvicorn ongigil.main:app --host 0.0.0.0 --port 8000
```

앱이 이 API URL을 바라보게 합니다. 배포는 이게 전부입니다 — 열쇠도, 유료 서비스도 없습니다.

---

## HTTPS는 필수 (선택 아님)

요즘 브라우저는 **보안 컨텍스트**, 즉 **HTTPS**(개발 중엔 `http://localhost`)에서만 **Geolocation**,
**Device Orientation**, **Wake Lock**을 허용합니다. 운영에서는 앱과 API를 모두 HTTPS로 제공해야 합니다 —
아니면 음성 안내가 위치를 못 얻고 화면도 못 켭니다.

- GitHub Pages는 기본 HTTPS입니다.
- 자체 호스팅 API는 TLS를 종단하세요(예: 무료 인증서를 쓰는 리버스 프록시).

---

## 정직한 화면 끔 한계

**이일국 박사님의 목표는 자동차 내비게이션처럼 화면을 끈 채 안내받는 것입니다.** 이 점을 솔직히 말합니다:

> 웹앱(PWA)은 화면을 완전히 끄거나 백그라운드일 때 **안정적으로 말하지 못합니다.** 페이지가 숨겨지면
> 브라우저가 배터리를 아끼려고 타이머·위치·`speechSynthesis`를 멈추기 때문입니다.

그래서 **v0.1은 화면 끔을 주장하지 않습니다.** 대신:

- **Wake Lock API**로 안내 중 **화면을 켜 두고**, 안내 화면에 그 점을 **분명히** 알립니다("화면을 켜
  두세요").
- 셔츠 주머니에 넣은 폰(화면 켠 채 바깥을 향함)에서도 들리도록 문장을 **짧게** 유지합니다.
- Wake Lock 미지원이면 화면을 수동으로 켜 두라고 안내합니다.

### 진짜 화면 끔으로 가는 길

**진짜 화면 끔, 백그라운드 음성 내비게이션은 안드로이드 네이티브 앱이 필요합니다** — 포그라운드 서비스는
화면을 끈 채 위치를 잡고 말할 수 있지만 브라우저는 못 합니다. 그 네이티브 앱이 문서화된 **다음
단계(설계서 §10, P3)**입니다. 그전까지 온기길을 화면 끔이 되는 것처럼 설명하지 마세요 — 화면을 켜 두며,
그 점을 정직하게 밝힙니다.

## 나중에 정밀 턴바이턴 넣기 (선택, 운영자 열쇠)

기본 호밍 안내는 지도가 필요 없습니다. 운영자가 **거리 단위 턴바이턴**을 원하면:

1. 기존 `Directions` 인터페이스(`route(from, to) -> steps[]`) 뒤에 제공자를 구현합니다 — 기본
   **`HomingDirections`** 옆에 **스텁**이 이미 있습니다.
2. 제공자 열쇠는 **환경변수/설정에만** 둡니다(예: `ONGIGIL_DIRECTIONS_KEY`). **열쇠를 커밋하지
   마세요** — 이 저장소는 열쇠를 담지 않고, 열쇠 없이 완전히 동작합니다.
3. 설정에서 제공자를 켭니다. 호밍 모드는 항상 쓰는 대체로 남습니다.

적합한 제공자: 카카오/네이버/구글 보행 길안내 API(운영자 선택, 각 제공자 약관 준수).

## 배포 점검표

- [ ] 앱을 정적 파일로(GitHub Pages 또는 정적 호스트) **HTTPS**로 제공
- [ ] API를 **HTTPS**로 접근 가능하게 하고 앱을 연결
- [ ] 열쇠 미커밋; 제공자 열쇠(있다면)는 환경변수/설정에만
- [ ] 지점 **만료** 동작으로 목록 최신 유지
- [ ] 안내 중 "화면을 켜 두세요" 안내 표시
- [ ] 프라이버시 기본값 켬: 뭉개기 활성, 안내 장기 저장 없음 ([04 · 프라이버시와 존엄](04-프라이버시와존엄.md))
