# 03 · 음성 안내 — 호밍 모델

온기길의 심장입니다. 기본 모드는 **지도 API도 열쇠도 필요 없습니다.** 브라우저의 **Geolocation**(위치)과,
가능하면 **Device Orientation**(나침반 방위)만 씁니다. 앱이 대상 지점까지의 방위와 거리를 계산해
**말하고**, 어르신이 움직이는 동안 반복합니다. 설계서 §4 기준.

핵심 생각: 어르신이 수레에 손을 얹은 채 **오직 귀만으로** 폐지 쪽으로 걸을 수 있어야 합니다. 차분하고
짧은 문장으로, 결코 말의 벽을 쌓지 않습니다.

---

## 단계별 흐름

```
  대상 지점 (geoApprox)                            어르신 폰
  ─────────────────────                           ─────────
                                    ┌── Geolocation → 현재 위치
                                    ├── Device Orientation → 방위(있으면)
                                    ▼
      방위 + 거리  ◄────────────  (현재 위치 → 대상)에서 계산
            │
            ├─ 방위 → 나침반 말 ("북동쪽")
            ├─ 방위 + 방위각 → 상대 회전 ("오른쪽으로 도세요")
            ├─ 거리 → 안내 + 카운트다운 ("50 m … 20 m")
            ├─ 거리 추세 → "가까워지고 있어요 / 멀어지고 있어요"
            └─ 임계 도달 → "거의 다 왔어요" → "도착했어요"
                    │
                    ▼   speechSynthesis(한국어 음성)로 말하고, 움직임에 따라 반복
```

---

## 1. 방위 → 나침반 말

어르신에서 지점까지의 방위(0°=북, 90°=동, 180°=남, 270°=서)를 사용자 언어의 **8방위** 말로 바꿉니다:

| 방위(°) | 말 |
|---|---|
| 337.5–22.5 | 북쪽 |
| 22.5–67.5 | 북동쪽 |
| 67.5–112.5 | 동쪽 |
| 112.5–157.5 | 남동쪽 |
| 157.5–202.5 | 남쪽 |
| 202.5–247.5 | 남서쪽 |
| 247.5–292.5 | 서쪽 |
| 292.5–337.5 | 북서쪽 |

나침반 말은 위치 두 개만 있으면 되므로 방위(heading) 없이도 항상 동작합니다.

---

## 2. 방위각 + 방위 → 상대 회전

**방위(heading)**를 알 수 있으면, 절대 방위를 어르신이 실제로 느끼는 **상대 회전**으로 바꿉니다.
`상대 = (방위 − heading + 360) mod 360` 라 하면:

| `상대`(°) | 말 | 뜻 |
|---|---|---|
| 350–360 / 0–10 | 앞으로 곧장 | 정면 |
| 10–45 | 오른쪽 앞으로 | 오른쪽 앞 |
| 45–135 | 오른쪽으로 도세요 | 우회전 |
| 135–225 | 뒤로 돌아서세요 | 뒤로 |
| 225–315 | 왼쪽으로 도세요 | 좌회전 |
| 315–350 | 왼쪽 앞으로 | 왼쪽 앞 |

이일국 박사님이 바라신 "왼쪽으로 조금 / 오른쪽으로 조금"의 감각을 **방위+방위각으로, 지도 없이** 만든
것입니다. 작은 흔들림에 떠들지 않도록 변화는 디바운스합니다.

---

## 3. 거리 안내와 카운트다운

거리는 계속이 아니라 **적절한 임계값**에서 말합니다:

- 의미 있는 변화마다(대략 **20 m**), 소음 없이 진행을 알립니다.
- **50 m 미만 카운트다운**: "50 m … 30 m … 20 m … 앞에 있습니다."
- 항상 **추세**와 함께: **"가까워지고 있어요"** 또는 **"멀어지고 있어요"**. 이 추세 덕분에 나침반이
  **없는** 어르신도 방향을 옳게 잡았는지 압니다 — "멀어져요"라면 돌아서면 됩니다.

---

## 4. 도착

| 거리 | 말 | 다음 |
|---|---|---|
| 약 15 m 이내 | 거의 다 왔어요 | 계속 안내 |
| 약 8 m 이내 | 도착했어요 | **가져감 / 없음** 표시 |

---

## 5. 음성

- Web Speech API **`speechSynthesis`**, 기본은 **한국어** 음성(영어 가능).
- **속도 조절 가능**(도우미가 설정에서 느리게).
- 문장은 **짧고 차분하며 정중하게** — 결코 문단으로 말하지 않습니다. **음소거**와 **다시 듣기** 버튼이
  항상 있습니다.

---

## 6. 나침반이 없으면 (대체)

많은 폰 — 특히 iOS — 은 Device Orientation에 권한이 필요하고, 어떤 기기는 쓸 만한 나침반이 없습니다.
방위를 알 수 없으면 앱이 **움직임에서 방위를 추정**합니다 — 걷는 동안 연속된 GPS 점을 비교해 진행 방향을
얻습니다. 그러면 안내는 여전히 **방향 + "가까워짐/멀어짐"**을 말하되, 회전 안내보다 추세에 더 기댑니다.

---

## 7. 선택적 정밀 턴바이턴 (업그레이드)

호밍 모델은 일부러 제공자 없이 만들었습니다. 나중에 운영자가 **보행 길안내 제공자 열쇠**를 더하면
안내를 **거리 단위 턴바이턴**으로 바꿀 수 있습니다.

- `Directions` 인터페이스가 있습니다: `route(from, to) -> steps[]`.
- 기본 **`HomingDirections`**(나침반/GPS, 열쇠 없음)와 실제 제공자용 **스텁**(예: 카카오/네이버/구글
  보행 API)이 함께 있습니다.
- 제공자 열쇠는 **환경변수/설정에만** 두며 운영자가 넣습니다. **이 저장소에는 열쇠가 없고**, 무료
  호밍 모드는 언제나 동작합니다. 넣는 방법: [06 · 배포와 한계](06-배포와한계.md).
